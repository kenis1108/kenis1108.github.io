考试冲刺全流程 ​

把用户给的考试材料（样卷/大纲/介绍）加工成一个可打卡、可刷题、可反馈调整的在线备考工作台，并承接后续错题分析闭环。整套流程已在一次真实备考（深圳大学学士学位英语，18 天冲刺）中完整跑通。

硬边界 ​

  • 不押题、不泄题、不承诺分数或通过；官方答案缺失时可以自拟参考答案，但必须显式标注"自拟非官方"。
  • 考试日期、题型、合格线以用户材料和官方通知为准；无法核验的标 [待确认]，估算值标 [计划假设]，不伪装成已确认事实。
  • 题库内容必须逐字来自用户提供的材料，解析题目后必须抽查回读核对，不得凭记忆补题。

核心流程 ​

1. 输入核对 ​

最小输入：考试名称、考试日期、可用时间（工作日/休息日各几小时）。缺目标分数时问一句或按合格线假设并标注。材料有多少用多少，没有样卷就只做计划不做题库。

2. 材料分析（决定策略的关键步骤） ​

  • 逐份读取用户材料，提取：题型结构、题量、分值、考试时长、官方答题要求。
  • 逐年交叉对比：题型是否改版（旧题型素材要拆解使用——还能练的当题库，不再考的明确跳过并在页面标注）。
  • 重复文件排查：用 md5 或全文 diff 比对各年样卷文件。同名不同年的文件可能内容完全相同（真实案例：2022-2025 四份样卷实为一套题），必须如实告知用户，避免题库虚胖。
  • 答案缺失的部分（如翻译、写作范文）如实标注，不虚构官方答案。

3. 时间与计划计算 ​

  • 用 Python chinese_calendar 计算剩余天数、节假日和调休补班日——不要心算。
  • 按用户确认的每日可用时间排任务；每天任务总量必须 ≤ 可用时间。
  • 计划数据落盘为 plan_data.json（字段规范见 references/data-schemas.md）：阶段划分、逐日任务（每个任务带材料/时长/验收标准）、阶段检测阈值、动态调整规则、考试当天时间分配策略。

4. 题库构建 ​

  • 解析样卷客观题为结构化 questions.json（字段规范见 references/data-schemas.md）：题干、选项、官方答案、考点标签、来源。
  • 考点标签是学习性标注（如"虚拟语气""固定搭配"），按知识点归类，供后续错题分析用。
  • 主观题（翻译/写作）：翻译给参考译文（自拟需标注），用户在页面三档自评（完全正确/部分正确/错误），后两档计错题。
  • 解析后必须抽查 3-5 题与原文比对，并程序化校验（选项数、答案合法性、题目总数）。

5. 交付：可打卡刷题网页 ​

调用 app_builder 构建，arch_type=jspage（需要本地状态保存）。页面四层结构：

  1. 打卡层：今日视图 + 全程计划（阶段分组）+ 任务勾选 + 复盘输入
  2. 刷题层：按套卷→模块分组，卡片式逐题作答，即时判分、显示考点；完形/阅读先呈现原文；翻译题输入译文自评
  3. 错题本层：自动汇总错题（我的答案/正确答案/考点/错误次数）+ 重做模式 + 一键导出纯文本（顶部统计 + 逐题明细，供用户复制发回聊天）
  4. 考情层：题型结构表、新旧题型差异、提分优先级、检测阈值、调整规则、假设与待确认标注

用户后续要求改计划/加题时，原地更新同一应用（传 target_app_id/target_app_token），保留用户已有打卡数据。

6. 错题分析闭环（用户发回错题本后） ​

按 references/wrong-book-analysis.md 的格式输出：考点分布统计 → 薄弱知识点清单（按错频和提分性价比排序）→ 针对性补弱任务 → 对原计划的调整建议。之后按需更新页面计划数据。

交付检查 ​

  • [ ] 每日任务总量 ≤ 用户每日可用时间
  • [ ] 样卷改版/重复/答案缺失三项排查都有结论并告知用户
  • [ ] 题库题目与原文抽查一致，答案全部来自官方文件（或已标注自拟）
  • [ ] 页面含错题本一键导出，导出文本可整段复制
  • [ ] 计划中的假设、待确认项在页面和交付说明中都有标注
