# 错题本分析规范（用户发回导出文本后）

用户从网页一键导出的错题本是纯文本：顶部统计（各模块错题数、考点分布）+ 逐题明细（题号、题干、选项、我的答案、正确答案、考点、来源）。收到后按本规范输出分析。

## 分析步骤

1. **解析统计**：错题总数、按模块分布、按考点标签分布（程序化统计，不心数）。
2. **聚类归因**：把考点标签归并为知识族（如"反义疑问句+倒装+强调句"→句法类），按族统计错误率 = 该族错题数 / 该族已做题数。
3. **区分错因**：同一考点反复错（≥2 次）= 知识漏洞；只错一次且集中在某套卷 = 可能是粗心/疲劳；主观题自评"部分正确"居多 = 输出能力问题不是知识问题。
4. **排序**：提分性价比 = 错误率 × 该考点在试卷中的分值权重。排前三的进"死磕清单"。

## 输出格式（直接回复用户，无需建文档）

1. **总体判断**（2-3 句）：错题规模、最薄弱的 2-3 个知识族、离合格线的差距评估
2. **薄弱清单表**：考点族 | 错误率 | 试卷权重 | 判定（知识漏洞/粗心/输出问题）
3. **补弱任务**：每个死磕点给 1 个具体任务（材料+时长+验收标准），挂到未来 3-5 天的对应任务位
4. **计划调整**：对照 plan_data.json 的 thresholds 和 adjustment_rules，说明哪些天怎么改；如需改页面则原地更新应用

## 调参铁律

- 连续两次错题分析同一考点族仍无改善 → 按调整规则降载：换更基础的材料重学，不再加题量。
- 分析结论必须同步落回计划：要么改 plan_data.json 并更新页面，要么明确说"计划不用动，原因 X"——不能只给分析不闭环。
- 用户只发了部分错题时，注明本次样本量，结论按样本量打折表述。
