公共免费 Webhook 接收端工具全指南 ​

一、前言 ​

开发、调试 Webhook 时，我们经常需要一个临时公网地址接收第三方推送的数据（GitHub、支付平台、CI/CD、钉钉/企业微信机器人等）。 自建服务成本高、本地无公网IP，因此各类免费公共 Webhook 接收站点成为调试首选。 本文整理海内外可用、零成本开箱即用的接收工具，区分国内直连、海外稳定两类，并说明适用场景、优缺点与安全规范。

核心用途：临时捕获 POST 请求、查看完整 Header / JSON Body、溯源请求IP、模拟回调测试。

二、海外免费工具（适合 GitHub、Stripe、海外云服务，需代理访问） ​

1. webhook.site（行业标杆，最常用） ​

  • 官网：https://webhook.site
  • 核心特性
    1. 无需注册，打开页面自动生成唯一 HTTPS 监听地址；
    2. 实时展示完整请求：请求头、Query 参数、Body、来源IP、UA；
    3. JSON 自动格式化高亮，支持一键复制 payload；
    4. 可自定义接口返回状态码、返回文本，模拟服务回调。
  • 免费限制
    • 匿名会话有效期 24h，最多存储 50 条请求记录；
    • 超时后所有请求记录自动清空。
  • 适用场景：临时快速查看推送原始数据、短期调试海外平台 Webhook。
  • 缺点：国内裸连访问缓慢或打不开。

2. Hook0 Play（大容量匿名接收端） ​

  • 官网：https://play.hook0.com
  • 核心特性
    1. 免登录即用，免费匿名会话支持存储 1000 条请求，远超同类工具；
    2. 自带转发能力，一键将 Webhook 流量转发到本地 localhost；
    3. 项目开源，可自行私有化部署；
    4. 支持历史请求重放，方便重复测试逻辑。
  • 适用场景：高频推送、长时间持续调试、本地开发流量转发。

3. Webhook Relay Bin（自带本地隧道，替代 ngrok） ​

  • 官网：https://webhookrelay.com/webhook-bin/
  • 核心特性
    1. 免注册生成临时监听 URL；
    2. 内置 CLI 工具，捕获到请求后自动转发到本机开发端口；
    3. 支持重放历史请求、自定义响应内容、过滤请求日志。
  • 适用场景：本地项目调试，不想额外安装 ngrok / cloudflare tunnel。

4. Svix Play（专业 Webhook 签名校验工具） ​

  • 官网：https://play.svix.com
  • 核心特性
    1. 专为标准化 Webhook 设计，内置 HMAC 签名校验面板；
    2. 适配 Stripe、海外SaaS支付、第三方登录等带签名回调；
    3. 配套官方 CLI，支持流量本地转发。
  • 适用场景：调试带密钥签名的支付、第三方业务回调，校验请求合法性。

5. HookListener（永久匿名地址） ​

  • 官网：https://www.hooklistener.com
  • 核心特性
    1. 匿名生成的链接不会随浏览器关闭失效；
    2. 无硬性请求数量限流，长期保存请求记录；
    3. 界面简洁无广告，一键重放任意历史请求。
  • 适用场景：需要长期固定临时地址，频繁切换浏览器调试。

三、国内直连免费工具（无需代理，适配钉钉/企业微信/阿里云/腾讯云） ​

1. UU在线工具 Webhook 监听 ​

  • 地址：https://uutool.cn/webhook/
  • 核心特性
    1. 国内服务器部署，国内网络无延迟直连；
    2. 一键启动监听，自动生成 HTTPS 公网地址；
    3. 完整记录请求时间、来源IP、请求头、表单/JSON载荷；
    4. 支持自定义接口返回内容、状态码。
  • 免费限制：半小时无新请求自动销毁链接，清空数据。
  • 适用场景：国内企业微信、钉钉机器人、腾讯云/阿里云告警回调调试。

2. WebtoolsPlanet Webhook Tester ​

  • 地址：https://webtoolsplanet.com/developer/webhook-tester
  • 核心特性
    1. 免登录打开即用，轻量化页面加载快；
    2. 自动解析 JSON、表单数据，区分 GET/POST 请求；
    3. 会话有效期 2h，最多保存 50 条请求。
  • 适用场景：极简快速调试国内各类云服务回调。

四、小众轻量化免费工具（按需选用） ​

  1. HookTest.dev
    • 地址：https://hooktest.dev/
    • 特性：24h有效期，单链接最多100条记录，支持自动转发消息到钉钉、Discord。
  2. Catchhook.app
    • 地址：https://temp.catchhook.app/
    • 特性：临时链接有效期48h，提供 Shell / Node 转发命令。
  3. MockLab（长期固定端点，需注册）
    • 地址：https://mocklab.dev/
    • 特性：免费注册赠送1个永久Webhook地址，每日200次请求额度，适合长期稳定调试。

六、标准使用流程（以 webhook.site 为例） ​

  1. 打开官网，复制页面顶部生成的唯一 HTTPS 监听 URL；
  2. 进入第三方平台（GitHub / 支付后台 / 钉钉机器人），填入该地址作为 Webhook 回调地址；
  3. 触发对应事件（代码提交、支付完成、表单提交）；
  4. 页面实时捕获 POST 请求，展开查看完整请求头、JSON 载荷、来源IP；
  5. 复制 payload 到本地脚本，模拟回调重复测试业务逻辑。

七、重要安全规范（必看） ​

  1. 禁止传入生产敏感数据 所有公共 Webhook 站点拥有请求数据查看权限，不要推送明文密钥、用户隐私、支付订单敏感信息，仅用于开发测试环境。
  2. 匿名会话有生命周期 绝大多数免登录临时链接会在 0.5~48h 自动清空记录，长期调试建议注册账号保存端点。
  3. 生产环境严禁依赖公共接收端 公共工具仅作调试；正式业务接收 Webhook 需要自建接口，配置 HMAC 签名校验、来源IP白名单、请求参数过滤，防止伪造攻击。
  4. 海外工具访问限制 webhook.site 等海外站点国内裸连大概率无法访问，调试国内业务优先选择国内工具。

八、补充：本地无公网替代方案 ​

如果不想使用第三方公共站点，可通过隧道工具把本地端口暴露为公网地址，自建临时接收端：

  • ngrok
  • Cloudflare Tunnel
  • VS Code Port Forwarding 优势：数据完全留在本地，无第三方泄露风险，适合处理敏感调试数据。
